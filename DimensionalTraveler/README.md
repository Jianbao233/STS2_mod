# 次元旅人

《杀戮尖塔 2》角色 Mod 的 `0.1.0` 开发版本。当前已完成完整卡牌、首批叙事进度、R01-R09 遗物、原生药水萃取，以及药剂背包查看与药水弹窗萃取入口的首版 UI。真实双进程多人核心链路已通过：攻击药水萃取、药剂包跨玩家投放、局部扩散和回响重放；后续主要是 UI 人工验收与交互调优、其余多人边界、表现资源和发布准备。

## 当前状态

### 已实现

- 次元旅人角色、12 张起始普通卡、起始遗物，以及不进入奖励池的兼容基础打防。
- 生机、挥发、腐化三类基础原理，以及催化、扩散、回响三类特殊原理。
- 战斗期药剂背包、永久系统牌 `药剂包`、动态主原理支付和按玩家隔离的隐藏战斗状态。
- 9 个药剂家族的普通、精制、杰作模型及各自 `+` 升级，共 27 个药剂模型。
- 45 张奖励卡，分布为普通 10 张、蓝色 18 张、金色 17 张。
- 显式生产、品质转化、局部／完整扩散、回响重放、回响派生药剂和实验记录链路。
- 8 张原生选择界面使用的原理 Token。Token 可由 `ModelDb` 解析，但不进入奖励池、起始套牌或正式内容计数。
- R01「稳定准则」至 R09「愿景之瞳」：配方首炼折扣、背包容量、轴向触发、药水保留与商店药水折扣均已实现并纳入遗物验收。
- 原生药水萃取：45 瓶共享池药水与 3 个冻结特例采用显式目录；萃取通过受所有者约束的同步 `GameAction` 结算。攻击药水在原生三选一提交前保留来源药水，产物统一以 `Extracted` 来源进入药剂背包；背包满时沿用原生手牌／弃牌溢出规则。
- 正式 UI 首版：战斗中提供独立药剂背包入口与只读卡牌查看屏；原生药水弹窗提供“萃取”按钮及按冻结 `ExtractionPlan` 生成的收益预览。UI 只展示和发起请求，资格复检与原子提交继续由后端负责。
- 叙事时间线：首次加载幂等补发 Epoch 1；旅人实际进入地图并结束第 1／2 局后顺序解锁 Epoch 2／3，角色始终可选。
- 全角色事件「未封的记录」：旅人与其他角色使用独立的本地页面和结算；旅人的转交仅在 R01/R02 间原生二选一、单发或回退 100 金。
- 7 位原版先古均已获得 `DIMENSIONAL_TRAVELER` 对白分支：涅奥、达弗、欧洛巴斯为正式文案，其余四位保留明确测试占位。
- 中英文角色、卡牌、能力、遗物、叙事、Epoch、事件与悬浮提示本地化。

- 中英文各 10 份本地化 JSON 均可解析；卡牌表各 202 个键、叙事相关的 `epochs/events/ancients/narrative` 四表均保持中英文键集合一致。
- 单人自动验收覆盖基础设施、配方支付、生产、品质操作、催化、扩散、回响、实验转化、遗物与原生药水萃取的目录／固定产物／攻击药水三选一／满背包溢出契约；运行时全量复验待显式授权启动游戏。
- 双人 host-drive 冒烟形成同一 `RunState` 中 `NetId 1/1001` 两位次元旅人，并验证：
  - 炼金原理、回合状态和药剂背包按玩家隔离；
  - 能量与次级资源只由出牌所有者支付；
  - 队友目标按指定战斗 ID 结算，双方快照观察到一致结果；
  - 原生选择的 `choiceId`、远端等待和远端提交均归属于正确玩家，主机不会代交本地选择。

- 真实双进程多人核心链路已通过：Host/Client 使用独立 MCP 与相同 run ID，Client 在本地药水栏请求托管注入、展示并提交原生三选一卡；随后双方确认萃取产物、基础／特殊原理增量与 RNG 摘要收敛。追加验证了药剂包取出护盾药剂后投向 Host、局部扩散的原生追加目标选择与双目标结算，以及回响重放冻结的双目标快照。

### 自动验收

统一入口会为每次运行生成独立报告到 `tests/acceptance/reports/acceptance_*.json`，并在项目根目录生成对应 `_runtime_acceptance_*.log`。

```powershell
# 已启动且可复用游戏 MCP 会话时
.\tests\acceptance\Invoke-Acceptance.ps1 -ReuseSession

# 明确同意启动无窗口游戏进程时，执行完整运行时验收
.\tests\acceptance\Invoke-Acceptance.ps1 -AllowStartGame
```

`-SkipBuild` 只适用于已明确部署当前 DLL/PCK 的重复探针；正式收口应省略该参数，让运行器先重建并部署正式 Mod 与测试适配器。

## 依赖边界

- **运行时依赖**：已订阅的 `STS2-RitsuLib`，兼容游戏 `0.109.0` 分支。
- **测试基础设施**：实际加载 KitLib `0.31.1`，用于游戏内调试、MCP 自动化和伪联机宿主。双人入口通过反射校验 KitLib 内部伪联机契约，正式 Mod 不新增 KitLib 编译或运行时依赖，也不修改 KitLib 源码。

## 源码职责

- `src/Alchemy/Backpack/`：药剂背包状态、选择流程和系统牌保护。
- `src/Alchemy/Production/`：显式生产、催化增幅与最终生产快照。
- `src/Alchemy/Resolution/`：药剂目标、扩散、回响和派生来源结算。
- `src/Alchemy/State/`：按玩家隔离的战斗状态与摘要。
- `src/Content/`：卡牌、能力、遗物、事件及角色卡池模型。
- `src/Progression/`：Epoch 故事列、首次加载补发和跑局结束顺序解锁。
- `src/Resources/`：炼金原理的注册、获取与支付。
- `src/Bootstrap/`：RitsuLib 与内容程序集初始化。
- `test-adapter/`：仅用于验收的夹具、快照、支付／选择审计和伪联机控制。
- `tests/acceptance/`：PowerShell 验收 DSL、套件与 JSON 报告。
- `DimensionalTraveler/localization/`：英文与简体中文本地化。

## 本地构建与部署

运行以下命令会编译 DLL、导出 PCK，并同步到项目 `torelease/` 和游戏的 `mods/DimensionalTraveler` 目录。

```powershell
.\build.ps1
```

构建缓存、PCK、`torelease/`、`release/`、验收报告和 `_runtime_acceptance_*` 运行日志均不纳入 Git。
