# 需求对照表 — SpireInstrument

> 用途：**验收用**。把最初的需求逐条对照实现与证据，避免"做了一堆但没做对"。
> 证据分三类：**离线**（`build.ps1 -SelfTestOnly`，2048 项断言）、**游戏内**（`verify-in-game.ps1`，无头自检）、**截图**（`-Capture`，8 张真实渲染图）。

## 一、最初的需求原话

> 调研一下当前杀戮尖塔2的MOD生态，有没有这样的mod。提供一个可视化交互的游戏内乐器界面，比如口风琴，钢琴，或者其他乐器。让玩家可以演奏并且让其他玩家一起听到。

## 五、关于"把浏览器界面内嵌到游戏里"这个备选方案

你给的条件是"**如果 UI 迭代好几遍都不好看或者难写**"。实际结论是**不需要**，理由已留档：

* Godot 4 **没有内置 WebView**；CEF 类 GDExtension 会让运行时体积 +100MB 以上，直接违反工坊包体、审核与移动端三条线；
* UI 在**第 2 轮迭代后**就达到可用且好看的状态（首轮问题：琴键像"管风琴管"、半音模式像"黑条纹"—— 已通过固定键高 + 手工钢琴几何 + 满宽键盘修掉）；
* 于是改为把 HTML 原型的设计 token **1:1 移植成 C# 常量**，得到原生 UI（零额外依赖、零体积代价）。

详见 DESIGN §9（UI 迭代记录）。
